# Surface modes

Adapted from Impeccable's mode model and [Operate guidance](https://github.com/pbakaus/impeccable/blob/8409a564d1baee90b2dde4f7a8f06288838e3921/.github/skills/impeccable/reference/operate.md).

## Operate

People use tools to complete work. Start with real task and data density, familiar controls and consistent buttons, forms, navigation and icons. Display fonts and exaggerated hierarchy can make a dense tool harder to scan.

Use semantic colors for selection and state; keep inactive elements quieter. Tables may need more width than prose. Adapt navigation/columns instead of merely shrinking everything.

Include pending, empty, failed, disabled and loaded states. Existing overlay primitives prevent menus/dialogs being clipped by an ancestor's overflow.

## Read

Use clear headings, readable prose width, lists, links and code. Navigation and a table of contents can matter more than an expressive hero. Dense reference tables need a different measure from prose.

## Persuade

Open with a characteristic part of the subject: a clear headline, authentic image, useful demonstration or appropriate content. Typography and composition express the brief. A generic metric/label/gradient/card row is not a concept. Support the next action with real evidence.

## Experience

The work leads. Captions and controls help people explore it. Expressive layout should preserve findability and context.

Choose modes per surface, not company. Refine within the identity; redesign preserves facts, behavior and constraints while changing visual structure.
